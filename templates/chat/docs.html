How it Works

Shy2Ask acts as a trusted intermediary. When you submit a request, we:

  • Validate: Ensure the request is lawful and respectful.
  • Relay: Contact the recipient via your chosen method (Email, Letter, or Phone).
  • Maintain Anonymity: Your identity is never revealed to the recipient.
  • Facilitate Communication: Relay responses back to you through our secure platform.

The backend now auto-resolves participant links. If you send a requester_user or target_user, the model fills the matching email automatically. If you only send an email and a matching user already exists, the related user field is filled during save.

Create request payload:

{
  "requester_name": "Asha",
  "requester_email": "asha@example.com",
  "requester_user": 12,
  "requester_alias": "HiddenAsha",
  "target_name": "Ravi",
  "target_email": "ravi@example.com",
  "target_user": 33,
  "description": "Can you call me this weekend?",
  "service_channel": "email",
  "call_minutes": 0
}

You may provide either email fields, user ids, or both. The model will normalize emails, auto-link known users, and create the initial request message automatically.

Data Model

Shared model behavior

  • Abstract timestamp models keep creation and update dates consistent.
  • Custom querysets/managers centralize participant filtering and eager loading.
  • Email and user relations stay synchronized at the model layer during save.

Proxy models

  • ActiveShyRequest represents non-completed requests.
  • ConversationMessage represents user-facing chat history ordered by creation time.

WebSockets (WSS)

Real-time updates are handled via Django Channels WebSockets.

Chat: ws://host/ws/chat/{request_id}/ or wss://host/ws/chat/{request_id}/

Notifications: ws://host/ws/notifications/

Swagger realtime contract: GET /api/realtime/docs/

JSON chat: ws://host/ws/chat/{request_id}/?format=json

Requester token auth: ?token={token}

Responder tracking auth: ?tracking_code={tracking_code}&format=json

Notifications: ws://host/ws/notifications/?token={token}

Send chat JSON:

{
  "type": "chat.message",
  "body": "Hello from the realtime client",
  "alias": "OptionalDisplayName",
  "reply_to_id": 123
}

Receive chat JSON:

{
  "type": "chat.message",
  "message": {
    "id": 1,
    "request_id": 123,
    "sender": "requester",
    "recipient": "target",
    "display_name": "OptionalDisplayName",
    "body": "Hello",
    "clean_body": "Hello",
    "direction": "outbound",
    "is_mine": true,
    "created_at": "2026-04-22T10:00:00+00:00"
  }
}

Messages created through the REST endpoints are also broadcast to connected chat clients.

Security & Privacy

Privacy is our core value. Messages are moderated before storage, emails are normalized before linking, and request access is guarded by authenticated ownership checks or the request tracking code.
